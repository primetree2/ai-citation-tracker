    Advanced · Capture a live network response locally

    The hosted dashboard cannot intercept another website. The optional local utility records response bodies before a prompt is sent. It needs Node.js 22+ and Chrome, not an API key. Login is manual in a dedicated browser profile.

    1. Download or clone the repository and open a terminal in its root folder.
    2. Run the command below. Log in in the browser it opens.
    3. Enable web search, send one prompt, and wait for the answer to finish.
    4. Press Enter in the terminal. Drop the saved capture JSON above. If evidence is missing or unsupported, the import reports that rather than inventing results. 
    node runner/capture.mjs --provider chatgpt

    Other capture targets: claude, gemini, perplexity, grok. Capture targeting is not a claim that their private browser-stream formats are supported. Gemini's private batchexecute and Grok's private nested format are currently unsupported; use their documented API JSON instead. No authenticated provider capture was live-tested for this release.

    What the numbers mean

    • Retrieved: present in the response's search or grounding results. This is not proof the full page was read.
    • Cited: a URL linked by structured answer citations or a resolved citation reference—not just any link in answer text.
    • Matched rate: retrieved-and-cited sources divided by observed retrievals. A dash means no observed denominator.
    • Query: a search query visible in supported tool fields. Missing query data is not zero searches.

    Supported saved response formats

    Provider format Retrieval evidence Citation evidence / limit
    ChatGPT saved chat metadata.search_result_groups Resolved inline references and content_references; active branch when available
    Claude saved chat Named web_search tool results Text-block citations; tool blocks must be included
    OpenAI Responses API web_search_call.action.sources URL annotations; request source inclusion when calling the API
    Anthropic Messages API web_search_tool_result Text-block web citations
    Gemini generateContent API Grounding chunks Grounding support indices; first candidate only, not a full search log
    Perplexity Sonar API search_results if supplied citations; citation-only when retrieval records are missing
    Grok / xAI completion API search_results if supplied citations / URL annotations; model must identify Grok or provider be explicit

    API formats are fixture-tested. That does not establish compatibility with each provider's consumer website, all API versions, or live accounts. SSE support is scoped in the capture guide. Unknown providers can use the explicit normalized schema.

    Full snapshots, only when present

    Run details retain full available snippets, publication dates, attribution, channel name, followers, verification, views, likes, description, and text timecodes. Missing metadata stays missing. No transcript or extra source page is fetched. Provider-visible status labels are not hidden reasoning.

    Privacy and storage

    Imports are parsed here and normalized evidence is stored in this browser's localStorage. No analytics, API keys, or import uploads are used. Hosting still makes normal asset requests; source links contact those sites. Browser storage is origin-wide, not encrypted, and not synced across devices. Export a backup before clearing it.

    Assignment status
